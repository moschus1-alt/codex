# 무한매수 · Toss Workspace

Vercel용 개인 투자 주문 워크스페이스. 라오어 **V2.2 · 40분할 계산안**, 최대 6종목, 공통 설정과 종목별 오버라이드, PAPER/LIVE 분리, 주문 사유 로그를 제공합니다.

> 현재 범위: **주문표를 만들고 주문별로 확인·전송하는 웹앱**입니다. 무인 자동매매나 완전한 V2.2 복제본이 아닙니다. 원문 카페 확인과 실계좌 검증은 미완료이며 LIVE는 기본 잠금입니다. MOC가 필요한 쿼터손절은 지원하지 않습니다.

## Vercel 배포

1. GitHub의 `moschus1-alt/codex` 저장소를 Import합니다.
2. **Production Branch: `infinite-buy-vercel`**, Root Directory: 저장소 루트, Framework Preset: **Other**, Node.js: **22.x**를 선택합니다. 기존 main을 배포하지 마세요. 필요하면 해당 브랜치의 Deploy를 실행하거나 Vercel 프로젝트의 Git 설정에서 Production Branch를 변경합니다.
3. Build Command는 `npm run build`, Output Directory는 `public`입니다. `vercel.json`에 설정되어 있습니다.
4. Vercel Marketplace에서 Upstash Redis를 연결하고 아래 환경변수를 등록합니다. Redis는 이 앱 전용 DB를 쓰세요.
5. Deploy 후 접속 비밀번호로 로그인합니다. 먼저 PAPER에서 시험합니다.

| 환경변수 | 용도 |
| --- | --- |
| `APP_PASSWORD` | 앱 로그인 비밀번호, 16자 이상 임의 문자열 |
| `SESSION_SECRET` | 세션 서명 키, 32자 이상 임의 문자열 |
| `UPSTASH_REDIS_REST_URL` | Redis HTTPS REST URL |
| `UPSTASH_REDIS_REST_TOKEN` | Redis REST 토큰 |
| `TOSS_CLIENT_ID` | 토스 Open API client ID |
| `TOSS_CLIENT_SECRET` | 토스 client secret |
| `TOSS_ACCOUNT_SEQ` | 토스 계좌 식별자 accountSeq (계좌번호와 다름) |
| `LIVE_TRADING_ENABLED` | 기본 `false`. 실거래 전송 활성화 때만 `true` |
| `STRATEGY_RULES_CONFIRMED` | 기본 `false`. 아래 계산안과 실제 주문 검증 후만 `true` |

비밀키를 GitHub, 채팅, 브라우저 저장소에 넣지 마세요. 환경변수 변경 후에는 재배포합니다. 계좌 식별자는 토스 공식 `GET /api/v1/accounts`로 확인합니다. 접속 비밀번호·API 키 입력용 공개 페이지는 제공하지 않습니다.

## 사용 순서

1. PAPER → 전략 설정: 종목당 원금, 수수료, 단일 주문 한도, 최대 6종목을 저장합니다.
2. 처음에는 종목별 가상 현금이 원금만큼 배정됩니다. 이미 진행 중인 사이클은 모의 잔고 입력에서 수량·평단·현금을 입력합니다. 원금 설정 변경은 기존 모의 현금을 자동 변경하지 않습니다.
3. 오늘 주문표에서 최초 LOC 한도가를 지정하거나 보유 잔고로 계산합니다.
4. 주문·체결에서 당일 고가와 종가를 넣어 모의 체결을 확인합니다. 입력 데이터는 자동 검증된 시장 데이터가 아닙니다.
5. 원문 대조와 PAPER 검증 후 필요할 때 LIVE를 활성화합니다. **동일 종목을 다른 전략으로 함께 운용하지 마세요.** 토스 계좌 전체 보유분을 한 전략의 잔고로 취급합니다.
6. LIVE → 토스 잔고 동기화 → 60초 안에 주문표 확정 → 15분 안에 각 주문을 확인해 전송합니다. 주문별 확인 문구가 필요합니다.
7. 접수 후 체결 상태 조회로 주문 상태·누적 체결수량을 확인합니다. 취소·정정은 토스 앱에서 수행합니다.

현재가 버튼은 API의 현재가와 데이터 시각을 조회합니다. 자동 갱신·예약 실행은 하지 않습니다. 화면에 보이는 접수는 체결을 뜻하지 않습니다.

## 구현한 계산안

- 원금을 40등분합니다. T = 잔여 매입원가 / 1회 매수금, 소수 첫째 자리까지 올림합니다.
- 별% = 10 − T/2. 전반 T<20: 평단/별지점에 각 반액 LOC, 후반: 별지점에 1회액 LOC.
- 별지점 매수는 센트 절삭 후 $0.01을 빼고, 별지점 매도는 센트 올림합니다. 매수·매도 가격 겹침을 방지하는 **구현 가정**입니다.
- 보유수량의 1/4을 내림해 별지점 LOC 매도, 나머지는 평단 +10% 지정가 매도합니다.
- 정수 수량만 지원하고 수수료를 포함해 예산 안으로 수량을 내립니다. 종목당 원금 잔여 한도도 적용합니다.
- 첫 진입은 사용자가 정한 LOC 한도가를 씁니다. 시장가로 자동 대체하지 않습니다.
- T≥39.1에서는 모든 주문을 막습니다. 원문 쿼터손절을 토스 앱에서 처리한 후 잔고를 다시 확인해야 합니다.

**원문 직접 확인 미완료:** [카페 원문](https://cafe.naver.com/infinitebuying/51593)과 [T 설명](https://cafe.naver.com/infinitebuying/48743)은 접근되지 않았습니다. 공개 설명과 대조한 계산안이며 원저자 인증·검증 프로그램이 아닙니다. 특히 잔여원가 기준 T, 분할체결 후 T, 초기 진입, 센트 보정, 소량 보유의 1/4 절삭, 쿼터손절 후 복귀는 본인 원문과 반드시 비교해야 합니다.

## 토스 API 및 운영 한계

[공식 REST 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json) v1.2.19를 확인했습니다. LOC는 `LIMIT + CLS`, 목표 매도는 `LIMIT + DAY`입니다. 현재 `CLS`는 미국 지정가만 지원하므로 `MARKET + CLS` MOC를 보내지 않습니다.

토스는 반대 방향 미체결 주문에 대해 `opposite-pending-order-exists`를 반환할 수 있습니다. 라오어식 매수·매도 동시 접수가 실제 계좌·세션에서 가능한지 검증하지 못했습니다. 거절 시 주문 방식을 임의 변경하지 않습니다. 휴장·마감 접수 가능 여부는 토스가 최종 판단하며, 앱은 자동으로 다음 거래일에 재시도하지 않습니다.

- 주문 요청 전에 영구 상태를 기록하며 동일 행은 재전송하지 않습니다. 토스의 clientOrderId는 10분 유효여서 영구 중복 방지는 Redis가 담당합니다.
- 응답 유실/오류는 보수적으로 `UNKNOWN`, 저장 후 장애는 `SUBMITTING`으로 남겨 차단합니다. **현재 이 상태의 복구 UI는 없습니다.** 토스에서 실제 주문을 확인하고 운영자가 Redis 기록을 대조해야 합니다. 확인 없이 기록을 지우거나 다시 주문하지 마세요.
- 부분체결은 누적 체결수량으로 표시합니다. 체결 장부를 자동으로 전략별 배분하지 않습니다. 다음 주문표의 잔고는 다시 동기화합니다.
- 이전 주문에 미체결/불명 상태가 있으면 같은 종목의 다음 주문표 생성을 차단합니다.
- 일시정지는 새 주문을 막지만 이미 접수한 주문을 취소하지 않습니다.
- 하루 한 주문표/모드/종목, 미국 뉴욕 날짜 기준입니다. 미전송 주문표만 폐기 가능합니다.
- 로컬 실행은 메모리 저장(재시작 시 초기화), Vercel은 Redis 필수입니다. LIVE는 Redis 없이는 활성화되지 않습니다.
- PAPER는 입력 OHLC 중 고가·종가만 사용하는 단순 모델입니다. 장중 매도 후 종가 매수를 가정하며 유동성·부분체결·시장 충격·세금·환율을 재현하지 않습니다.
- 서버 인증, HttpOnly 세션, 동일 출처 검사, Redis 원자적 상태 변경을 적용했습니다. 1인 계좌용이며 다중 사용자용이 아닙니다.
- 무인 예약실행은 미구현입니다. Vercel Hobby Cron은 일 1회/정확한 실행시각 보장 없음이므로 장마감 주문 스케줄러로 단순 적용하지 않았습니다.

## 기존 프로그램에서 이어온 것

`toss-momentum-trader-reviewed.zip` 최신 v10의 설정 검증, PAPER/LIVE 분리, 거래 사유 기록과 이전 SplitTrader의 최대 6종목·공통/개별 설정 구조를 참조했습니다. Python/FastAPI/SQLite 상시 실행 구조를 Vercel Node Function + Redis로 재구성했습니다. 급등주 거래대금 조건, MACD/RSI 진입조건, 7슬롯 손익 설정은 V2.2 전략과 달라 가져오지 않았습니다. 제작 지침은 [docs/BUILD_PROMPT.md](docs/BUILD_PROMPT.md)에 있습니다.

## 로컬 실행 및 검증

Node.js 22 이상. 외부 npm 의존성 없음.

```sh
cp .env.example .env
# .env의 비밀번호와 세션 키 설정
node --env-file=.env server.mjs
npm test
npm run build
```

http://localhost:3000 접속. 외부 계좌 연결 없이 PAPER 이용 가능. `npm test`는 외부 네트워크와 실제 주문을 사용하지 않습니다.

13개 테스트 통과: 주문 계산 경계·쿼터 구간 차단·수수료 예산·초기진입·모의 체결·과매도 방지·미국 날짜·동시저장 충돌·세션·CSRF·PAPER API·LIVE 잠금·실제 주문 형식(모킹)·부분체결·타임아웃 재전송 차단. 문법 빌드 성공. 실제 브라우저 UI, 실제 토스 주문, 실제 Redis 및 Vercel 배포는 미검증입니다.
